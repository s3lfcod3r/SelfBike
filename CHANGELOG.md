## 1.4.59 · November 2026
- 🇬🇧 **Assist shown as an offset, not a raw value + more read-outs**: the write confirmed on the bike (Flow reads back the value, no gate). Assistance is an offset, not a percent – raw 100 = standard, 10 raw points per step, so the UI now shows and takes steps (e.g. 0, +1, −5), clamped to the bike's range, instead of a raw number that tempted writing to the edge. Added read-only: whether assist-mode change is possible at all (6214), and the motor power and torque limits (6277/6278).
- 🇩🇪 **Unterstützung als Versatz statt Rohwert + mehr Auslesewerte**: Der Schreibvorgang ist am Rad bestätigt (Flow liest den Wert zurück, kein Gate). Die Unterstützung ist ein Versatz, kein Prozent – Rohwert 100 = Standard, 10 Rohpunkte je Stufe; die UI zeigt und nimmt jetzt Stufen (z. B. 0, +1, −5), geklemmt auf den Bereich des Rades, statt eines Rohwerts, der zum Schreiben an die Kante verleitet. Neu nur lesend: ob eine Fahrmodi-Änderung grundsätzlich möglich ist (6214) sowie die Motor-Leistungs- und Drehmomentgrenze (6277/6278).

## 1.4.58 · November 2026
- 🇬🇧 **Assist-mode write block now shows per mode with limits (not gated on the flag)**: the write block now appears for every active mode whose limits came back, independent of the "manufacturer-adjustable" flag – the flag is shown only as a hint. Confirmed by decompiling the Flow app: on Gen5 UDAM is alive (same addresses 4240/4242/4243/4244/4246), the message is just extended, the config id is encoded the same way, and Flow does not check that flag before writing. So the flag is not a write gate.
- 🇩🇪 **Fahrmodus-Schreibblock erscheint jetzt je Modus mit Grenzen (nicht am Flag gekoppelt)**: Der Schreibblock erscheint jetzt für jeden aktiven Modus, dessen Grenzen zurückkamen – unabhängig vom „vom Hersteller änderbar"-Flag, das nur noch als Hinweis danebensteht. Belegt durch Zerlegen der Flow-App: Auf Gen5 ist UDAM aktiv (gleiche Adressen 4240/4242/4243/4244/4246), die Nachricht ist nur erweitert, die ConfigId wird genauso kodiert, und Flow prüft das Flag vor dem Schreiben nicht. Das Flag ist also kein Schreib-Gate.

## 1.4.57 · November 2026
- 🇬🇧 **Assist modes: single, clamped write attempt (ECO+, experimental)**: the limits came back plausibly, so the encoding is proven and the "not adjustable" from 4246 is a real answer – it is not the rider lock. SelfBike now offers a careful one-mode experiment on ECO+: it reads the current values first (so the delta is visible), then changes only the assistance, clamped to the bike's own limits, leaving top speed and everything else untouched, and reads back. A factory reset button sits next to it. The read-back only proves the value was saved, not that it takes effect – you have to ride in that mode to see, which the UI states. A top speed over the bike's limit is refused by the safety guard.
- 🇩🇪 **Fahrmodi: einzelner, geklemmter Schreibversuch (ECO+, experimentell)**: Die Grenzen kamen plausibel zurück, die Kodierung ist also belegt und das „nicht änderbar" von 4246 ist eine echte Antwort – es ist nicht der Fahrer-Riegel. SelfBike bietet jetzt ein vorsichtiges Ein-Modus-Experiment an ECO+: liest zuerst die Ist-Werte (damit das Delta sichtbar ist), ändert dann nur die Unterstützung, geklemmt auf die Grenzen des Rades, lässt Höchstgeschwindigkeit und alles andere unberührt, und liest zurück. Ein Werks-Reset-Knopf steht daneben. Das Rücklesen beweist nur das Speichern, nicht die Wirkung – die zeigt sich erst beim Fahren, was die UI sagt. Eine Höchstgeschwindigkeit über der Rad-Grenze lehnt der Sicherheits-Guard ab.

Die reine Anzeige der Fahrmodi bleibt in jedem Fall.

## 1.4.51 · November 2026
- 🇬🇧 **Self-test read-back now waits and retries**: some control units (e.g. ABS) go briefly quiet right after the clear command and then answer with an empty frame – reading back immediately looked like "not readable". The read-back now waits ~1.5 s and retries once (the pre-read retries too), so a short absence is no longer mistaken for an unreachable channel. ABS stays a target for now; if it still reads "not readable" even in a fresh session, its channel is unusable there and it should be dropped.
- 🇩🇪 **Selbsttest-Rücklesen wartet und wiederholt**: Manche Steuergeräte (z. B. ABS) sind direkt nach dem Löschbefehl kurz still und antworten dann mit einem leeren Rahmen – sofortiges Rücklesen sah wie „nicht lesbar" aus. Das Rücklesen wartet jetzt ~1,5 s und wiederholt einmal (auch das Vorab-Lesen), sodass eine kurze Abwesenheit nicht mehr für einen unerreichbaren Kanal gehalten wird. ABS bleibt vorerst Ziel; meldet es auch in einer neuen Sitzung weiter „nicht lesbar", ist der Kanal dort unbrauchbar und sollte entfernt werden.

## 1.4.50 · November 2026
- 🇬🇧 **Self-test wording refined**: on a non-empty memory the self-test is now clearly just a read – it deletes nothing and points to the normal (selection-based) clear instead. Count wording is back where it helps, with correct singular/plural ("one entry" / "N entries"). The transport already distinguishes "frame received" from "no answer" (a missing answer is a timeout at the root), so the proto3 default of return value 0 stays correct and the read-back remains the second safety.
- 🇩🇪 **Selbsttest-Formulierung geschärft**: Bei nicht leerem Speicher ist der Selbsttest jetzt klar nur ein Lesevorgang – er löscht nichts und verweist stattdessen auf die normale (auswahlbasierte) Löschfunktion. Die Zahl steht wieder da, wo sie hilft, mit korrektem Singular/Plural („ein Eintrag" / „N Einträge"). Der Transport unterscheidet „Rahmen angekommen" von „keine Antwort" (fehlende Antwort ist ein Timeout an der Wurzel) bereits sauber, also bleibt der proto3-Default von Rückgabewert 0 richtig und das Rücklesen die zweite Sicherung.

## 1.4.49 · November 2026
- 🇬🇧 **Self-test made safe and honest (important fix)**: the pipeline self-test no longer deletes anything on a non-empty memory – it now re-reads the state while blocked and, if entries are present, deletes nothing and refreshes the (stale) display instead of silently clearing real faults. Success is now derived from the operation RETURN_VALUE plus a consistent read-back (still readable and empty), not from the transport status or a defaulted value – so a control unit that reads "not readable" after the run is no longer reported as success. Every step (block/delete/read-back/unblock + status) is logged. ABS counts as not proven until a clean self-test run.
- 🇩🇪 **Selbsttest sicher und ehrlich gemacht (wichtiger Fix)**: Der Pipeline-Selbsttest löscht auf einem nicht leeren Speicher nichts mehr – er liest den Stand jetzt im blockierten Zustand erneut und löscht bei vorhandenen Einträgen nicht, sondern aktualisiert die (veraltete) Anzeige, statt echte Fehler still zu löschen. Der Erfolg kommt jetzt aus dem Operation-RETURN_VALUE plus einem konsistenten Rücklesen (weiter lesbar und leer), nicht aus dem Transport-Status oder einem Default-Wert – ein Steuergerät, das nach dem Lauf „nicht lesbar" meldet, gilt nicht mehr als Erfolg. Jeder Schritt (Block/Löschen/Rücklesen/Unblock + Status) wird protokolliert. ABS gilt bis zu einem sauberen Selbsttest-Lauf als nicht bewiesen.

Die Lösch-Evidenz steht jetzt in drei Stufen statt pauschal „verifiziert": Motor und Bedieneinheit durch echtes Löschen bewiesen, Akku per Selbsttest, ABS aus der Zählantwort abgeleitet. Die Akku-Schlüsselnummer (6195) wird jetzt als Text gelesen (nur lesend; Diebstahlschutz-Feld).
